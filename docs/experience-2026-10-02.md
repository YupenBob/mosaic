# 2026-10-02 实际体验排查与修复

全项目解耦上线后，针对真实操作继续检查。保留原页面风格、内容地址与独立媒体工作流。

## 发现与影响

| 场景 | 实际问题 | 修复 |
| --- | --- | --- |
| 视频打开 | 生产冷访问中，模块逐层下载，播放器模块约 5583ms 才加载完 | 发布阶段打包一个 app ESM；源码仍按职责拆分，组件独立初始化 |
| 首页搜索 | 索引很小，但 filter/search 等待前置模块；首次冷访问搜索模块约 2640ms | 索引与组件初始化直接开始；加载前输入保留并重放 |
| 视频缓存 | 原生无 crossorigin 的预加载把没有 ACAO 的响应缓存下来；HLS 请求命中后被 CORS 拦截 | 显式 anonymous CORS、preload=none；稳定请求命名空间同时用于 master、档位、分片和 MP4 的 MSE 请求 |
| 视频带宽 | 未播放的实例也开始 HLS 分片下载 | 默认点击播放后 startLoad；提前点击保存意图并在初始化后执行 |
| 首次画面 | 没有元数据时视频尺寸不稳定，播放按钮可被控制条遮挡 | 从清单比例预留尺寸，缺失时使用可配置比例 |
| 失败与低档 | 清单失败长时间重复等待，设备首选档不存在时不选择已发布低档 | 致命清单错误直接回退 MP4；只在实际可用档位中选择 |
| 播放恢复 | MSE blob URL 每次变化，存储位置不能复用 | 使用稳定媒体 ID 记录与恢复位置 |
| 点赞 | 事件绑定等待统计接口，用户看到按钮但不能立即操作 | 先绑定交互；迟到统计不覆盖本页已发生的操作 |
| 后台打开 | 健康、容量、流量、列表、构建请求串行/聚合阻塞整个页面 | 操作入口先显示；服务分别刷新，错误提供局部重试 |
| 后台请求 | 多处重复配置/构建请求；空闲仍高频轮询 | 在途读取合并、有限缓存、消费者独立取消；活动/空闲/隐藏页采用不同间隔 |
| 上传确认 | PUT 成功但完成确认失败会退回整文件重传；任务 ID 被丢弃 | 保留完成回执；确认失败只重试确认，处理失败只重试任务 |
| 分片进度 | 并发分片覆盖进度，末片被当成完整分片计数 | 汇总已完成与上传中字节，进度单调、确认前最多 99% |
| 封面与顺序 | 卡片猜测固定 processed 路径；任意视频封面写成 video:0；孤立封面无法预览 | 用清单实际预览和实际视频索引；孤立封面单列；前后台共用排序 |
| 编辑期间 | 后台媒体轮询重建文本框，丢失光标与撤销历史 | 后续状态刷新只更新媒体节点，保留文本框 |
| 摘要 | 自动摘要泄漏内容块标记 | 摘要提取先移除独立媒体标记 |

冷访问时间来自同一台 Windows 主机的真实生产网络，属于单次诊断样本，不代表性能中位数或移动设备基准。原生成器性能对照仍见 [performance.md](performance.md)，本次不宣称生成器提速。

## 验证方法

- `npm run check`：原 38 组 Worker、内容块、上传、任务、配置、精简列表与独立构建契约，以及新增 API 客户端和媒体列表用例。
- `npm run test:e2e:local`：原移动端/主题/可访问性、画廊、音乐、播放列表，加真实 HLS 和 MP4。缓存用例使用真实 HTTP 服务，不拦截媒体请求；先预热无 Origin 旧 URL，再播放新请求并暖缓存重载。
- `npm run test:admin:local`：7 页面×2 主题 axe，加慢统计、重复读取、复合筛选、封面、文本框保留与三种上传路径。确认失败验证只有一次 PUT、两次确认；处理重试不会增加上传或确认次数。
- 新的 HLS fixture 为本地合成蓝色视频，6 秒、320×240、10fps，提交的 base64 文件约 24KB；测试期间不运行 FFmpeg，也不读取用户原文件。

旧浏览器用例曾调用 `page.route`，它会关闭 HTTP 缓存，因而没有暴露线上缓存/CORS 故障。保留这些用例验证 UI 逻辑，同时增加缓存开启的真实网络测试。Windows WebKit 不等同于真实 Safari：本地真实 MP4与 HLS 控制逻辑分别验证，实际 Safari 仍应独立验收。

## 兼容与发布

新增媒体列表字段是兼容扩展；`covers` 不占用内容图片索引。播放/后台参数不进入媒体处理指纹，不触发已有媒体转码。沿用 main 与 codex/project-refactor，发布前同步了用户新增的 my-post。宣传视频目录与备份脚本不纳入提交。

构建不下载原始媒体或调用 FFmpeg的约束保持不变。先通过离线与分支工作流，再兼容发布 Worker、后台和站点；生产缓存与播放结果在发布后记录。

新增发现：生产 JS 的 Cache-Control 为 public, max-age=14400, must-revalidate。同名覆盖会让老访客在 4 小时内继续用旧代码。前台 app 现在使用内容哈希文件名；后台发布前生成暂存目录，为入口、样式和整套模块依赖写入相同内容版本，不改源文件与 Pages 代理。浏览器回归直接运行暂存后的后台。
